# Privacy, egress, licensing and fork identity

Status: research, 2026-11-11, read from `origin/main` at `0d4fe36f3`. Nothing here was run against a built extension: findings come from reading code, manifests and workflows. Not legal advice. Severity words: **confirmed defect** (the code does it, I read it), **probable** (depends on a condition I could not test), **theoretical** (needs an unusual setup).

### Verdict on "collects no telemetry"

True for the VSIX in the sense of analytics: no analytics SDK is in the code and the embeddings model never downloads. Two qualifications belong next to the claim. F7: the CLI exports metrics to any OTLP endpoint in the environment. F1 and F2: identifying requests (machine id, shared key) go to a third-party service that is neither the user nor us. Until F1 is fixed, the release-notes sentence should add "the web search tool sends your query to a third-party search proxy", or the tool should be removed.

## 3. Proposal: runtime egress allowlist test

1. **Static layer** (cheap; runs in `merge-gate`). A vitest scans `core`, `extensions/vscode/src`, `extensions/cli/src`, `gui/src` and `packages/*/src` (tests and comments excluded) for `https?://` literals and `new URL(` bases, resolves each host and compares it to a checked-in `egress-allowlist.json` (host, file, reason, class). A new host fails with its file and line. The same list drives a test that the webview CSP names no host outside it.
2. **Runtime layer** (e2e). In `extensions/vscode/e2e` and the CLI smoke test, start with a `--require` shim that wraps `fetch`, `http.request`, `https.request`, `net.connect` and `dns.lookup` and records hosts, using a default config and a local fake provider. Drive start-up, the settings page, and one chat that calls every built-in tool, including `search_web` and `fetch_url` against a stub. Assert that recorded hosts are a subset of loopback and the stub. Attach the capture to each release (fork-plan section 8).
3. **Bundle guard.** Fail if `posthog`, `sentry`, `segment` or `@opentelemetry/exporter` appears in the VSIX `out/` bundle (the CLI keeps OTLP until F7 is decided).

I did not retrieve Continue Dev's branding policy, so the only established fact is Apache-2.0 section 6: no trademark licence is granted. Manifest: `name continuous`, `displayName Continuous`, `publisher b1tninja`, `license Apache-2.0`, and `repository`, `bugs`, `homepage` and `qna` all point at `github.com/b1tninja/continuous`; `icon media/icon.png`. `main.yaml` publishes to the Marketplace by OIDC trusted publishing under the `marketplace` environment, and to Open VSX with `ovsx@1.3.0` when `VSX_REGISTRY_TOKEN` exists (`publish-openvsx`, repository-guarded). The proposed-API "agents" builds go to the GitHub release only.

Checklist. README on the listing: `extensions/vscode/README.md` opens with the unofficial-fork disclaimer (met). LICENSE, repository and bugs links (met). Privacy statement: the Marketplace has no field for it, so link `PRIVACY.md` from the README. Verified publisher: needs a domain the owner controls and a DNS TXT record, plus Marketplace age and activity rules I did not check; decide whether it is worth a domain. Open VSX: publishing needs the Eclipse publisher agreement signed by the owner; confirm before relying on that job. The listing README embeds a shields.io image; harmless, and the Marketplace proxies it.

## 6. PRIVACY.md proposal

> **Privacy.** Continuous runs on your machine. It has no account, no server of ours and no analytics.
>
> **Stored locally.** Settings and models in `~/.continuous` (copied from `~/.continue` on first start); chat sessions and history; the audit trail of tool decisions (on by default, masked and capped; `audit.enabled: false` turns it off); logs; checkpoints; plan files in your project. API keys go to VS Code secret storage. Retention follows the scrub-on-write defaults from #560: [state the numbers here].
>
> **Sent to the model providers you choose.** Your prompts, the files and tool output the agent reads, and the conversation, to the endpoint you configured. Nothing else is added.
>
> **Sent elsewhere only if you use it.** MCP servers you add; web pages you ask it to fetch or index; the web search tool [name the provider once F1 is decided]; one Chromium download if you accept it.
>
> **Not sent.** No usage data, no crash reports, no machine id. Terminal commands start with a scrubbed environment. The terminal agent exports metrics only if you set `OTEL_*` variables yourself, to the destination you set.

Every sentence needs the allowlist test of section 3 behind it before the file ships.
