When choosing, the order of preference was:

1. the research's recommended option;
2. the safer, reversible and privacy-preserving default;
3. consistency with what has already shipped;
4. no new egress and no telemetry.

A decision that spends money, is public-facing or about identity (names, branding, listings, licensing), touches credentials or repository settings, or is hard to reverse is not taken here. It is listed under [Kept for the owner](#kept-for-the-owner) with a one-line recommendation.

## Summary

- **Decided here: 200 rows** in the area tables below. Many rows bundle several of one note's sub-questions (the Copy as Markdown list, the taint model, the wizard), so the number of individual questions answered is higher.
- **Recorded, not re-decided: 16** decisions taken by the lead earlier in this session (section 1).
- **Kept for the owner: 53 rows** (the last table).
- Where two notes disagreed, the rationale cell names both and says which one wins. This happened for the loopback `serve` token, `readPolicy`, spotlighting, cloud keep-warm and the name of the lock section.

The five decisions with the most user-visible effect:

1. **Headless runs stop allowing everything (CO2).** In headless runs (`-p` and `serve`), commands run at the person's own levels (Cautious) and anything that would ask is refused. `--auto` or `--policy handsOff` opts back in, with a one-line stderr notice, and there is a one-release escape hatch. Every script and the bench harness see this change.
2. **A loopback `cn serve` needs a token by default (S1-L1, PAR Q6).** The token is printed once and stored with user-only permissions, and `--no-token` is a loud opt-out. The release notes name this as a breaking change for scripts.
3. **Editing an earlier message no longer throws away the later turns (NI7).** The replaced turns are saved as a copy, and an undo line appears. Esc on an empty input stops a streaming reply (NI8).
4. **New tools from a changed MCP server stay hidden until approved (TR4).** In Plan mode, the only MCP tools are read-only ones from servers the person trusts (TR2). Unattended runs get no MCP tools unless the person lists them (TR1).
5. **Home is masked as `~` for every provider (ENV 2).** The IDE gets the same system line as the CLI (ENV 3). Certain parse errors are refused before the approval card (ENV 4). The executor runs non-interactive, with closed stdin, `PAGER=cat` and real exit codes (ENV 5).

Decisions that need code are marked **code** in the Consequence column. Every other decision is a documentation change, a confirmation of current behaviour, or a gate on a later measurement.
